# @cmdless/ui-sdk

Shared types and helpers for building on cmdless UI. Everything a consumer or a `@cmdless/ui-runtime` build needs, split by where it runs.

## Exports

- **`@cmdless/ui-sdk/node`** — for the process invoking cmdless UI (or the Electron main process handling it).
  - `CmdlessUI` dispatches `show`/`message-box` requests — by default by spawning `@cmdless/ui-runtime` (via `runAsRuntime`), or with a custom `dispatch` for handling a request in-process (e.g. a window's own preload asking for a nested dialog).
  - `createShowCommand({ params, result?, dispatcher?, cmdlessRoot?, transport? })` — the usual way to build a one-off "show a window" CLI command: takes a `params(input)` callback that returns the `ShowParams` to use, and returns an `(input, parent?) => Promise<Out>` function. If a dev server has published its own URL via `CmdlessEnv.url` (see below), it always overrides `params()`'s `type`/`source` - individual commands never need to check for that themselves. Pass `transport` to also stand up a `@cmdless/rpc-sdk/ws/node` server per invocation and pass its address through as `--address`, for a renderer that needs to talk directly to this process.
  - `CmdlessEnv` — typed accessors for the `CMDLESS_ROOT`/`CMDLESS_APP`/`CMDLESS_URL` environment variables. A dev-mode Vite plugin (see `apps/agent-runner`'s `vite.config.ts` for the pattern) can publish its dev server's URL under `CmdlessEnv.url` before spawning a consumer's bin, so `createShowCommand` picks it up automatically instead of the built renderer.
  - `BinChannel` — a small socket-based protocol (built on `@cmdless/rpc-sdk`'s Node socket transport) for a bin process to talk to a long-running child it spawns (e.g. Electron), without using `child_process`'s `'ipc'` stdio channel - that combination is a documented source of Electron `app.whenReady()` hangs ([electron/electron#17044](https://github.com/electron/electron/issues/17044)). Call `BinChannel.start(onMessage)` in the parent *before* spawning (fold its returned `env` into the spawn call), and `await BinChannel.connect()` at the top of the child to get a `send(message)` function back.
  - Package-caching helpers: `ensurePackage`, `runAsPackage`, `runAsRuntime`, `runPackage` (blocking, captures stdout), `spawnPackage` (non-blocking, for a long-running process), `findLocalBinPath` (resolves a package's `bin` entry to an absolute path via `findPackageJSON`, given the caller's own `import.meta`).
- **`@cmdless/ui-sdk`** — platform-agnostic: the `Params`/`ShowParams`/`MessageBoxParams` types, `cmdlessIPC` (the [`@cmdless/rpc-sdk`](../rpc-sdk) protocol definition shared between a window's preload and the Electron main process - main ↔ renderer only, not a consumer's own backend), `createElectronIPC`, and a small typed `Emitter` used internally.
- **`@cmdless/ui-sdk/browser`** — for code running in a cmdless-hosted window. `CmdlessRenderer` wraps `window.cmdless`, the object the preload script exposes, and can also connect directly to a consumer's own backend over `@cmdless/rpc-sdk/ws` using the address `cmdlessIPC`'s `connectionInfo` request hands back.
